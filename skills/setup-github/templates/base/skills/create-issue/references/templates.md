# Issue テンプレート

type に応じて使い分ける。骨格は 状況 → 詳細 → 完了条件 → 参考。
`.github/ISSUE_TEMPLATE/*.yml` を持つリポジトリでは、その節構成に合わせる。

## fix（バグ報告）

```markdown
## 概要
<!-- 何が起きているかを1〜3文で -->

## 再現手順
1. 
2. 

## 期待する動作

## 実際の動作

## 環境
<!-- バージョン・OS・ブラウザなど。該当しなければ「特になし」 -->

## 完了条件
- [ ] 

## 参考
<!-- ログ・スクリーンショット・関連 Issue。なければ「なし」 -->
```

## feat（機能要望）

```markdown
## 解決したい課題
<!-- 何が困っているか -->

## 提案する内容

## 代替案
<!-- 検討した他の方法。なければ「なし」 -->

## 完了条件
- [ ] 

## 参考
<!-- 関連 Issue / PR / 参考リンク。なければ「なし」 -->
```

## その他（docs / style / refactor / perf / test / build / ci / chore）

```markdown
## 概要

## 背景・目的
<!-- なぜこの作業が必要か -->

## 完了条件
- [ ] 

## 参考
<!-- 関連 Issue / PR / ドキュメント。なければ「なし」 -->
```
