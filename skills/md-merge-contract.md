# 要マージ Markdown の統合手順（setup-github / setup-unity / setup-sync 共通）

`apply.mjs` は `.claude/rules/*.md` と `.claude/CLAUDE.md` を**書かない**。既存があり内容が
異なるときは「要マージ」として報告するだけで止める。プロジェクト側で育った記述を機械的に
潰さず、かつテンプレ更新を機械的に握り潰さないための委譲であり、**統合は Claude が行う**。

この工程を飛ばすと、テンプレートの更新はその配備先に永久に届かない。

## 手順

`apply.mjs` の出力に「要マージ」節があれば、そこに挙がったファイルを**1 つずつ**処理する。

1. 「現物」と「テンプレ」の両方を Read する（どちらのパスも出力に載っている）
2. 統合した**全文**を作り、**現物のパスへ Write** する
3. 何を採り、何を残し、何を消したかを結果報告に含める

## 判断基準

- **テンプレが扱っている話題は、テンプレ側を正とする**
  - 文面が変わっていれば新しい方を採る
  - テンプレから消えた項目は現物からも消す
- **テンプレが扱っていない、プロジェクト固有の記述は残す**
  - 独自の節・箇条書き・例外規定など。位置関係も壊さない
- **現物の独自記述がテンプレの新しい記述と正面から矛盾する場合**
  - 勝手に決めず、両者を並べてユーザーへ提示し、どちらを採るか確認する（下記）

## 矛盾したときの扱い

統合はユーザーのセッションで走る。**その場で聞けるなら聞く**のが原則。

聞けない状況（ユーザーが席を外している、複数リポジトリを一括で処理している最中など）でだけ、
統合を止めずにこうする。保留するとテンプレ更新がその配備先に永久に届かないため。

1. テンプレ側を採って統合を完了させる
2. 何と何が矛盾し、どちらを採ったかを
   `~/.claude/plugins/data/project-setup/sync-notes.md` へ追記する（無ければ作る）
3. `sync-run.mjs --phase=publish` がその中身を PR 本文の「## 要確認（テンプレと現物が矛盾）」へ
   転記して、メモを消す

判断が消えるわけではない。**PR レビューが人間の判断の場になる**（この PR は merge されない）。
迷ったら聞く側に倒すこと。

## CLAUDE.md の注意

テンプレが配るのは**節**であって全文ではない。ファイル全体を置き換えず、該当節だけを
更新する。`## 開発ワークフロー` 見出しが既にあれば、その節の中で統合する（見出しを増やさない）。

setup-github と setup-unity は同じ見出しへ別々の箇条書きを配る。片方を統合するときに
もう片方の行を消さないこと。
